## Production-ресурсы

Главная подключает `home.min.css?v=78` из коммита `16abbcb`, остальные страницы подключают `styles.min.css?v=79` из того же коммита. CSS загружается через jsDelivr с привязкой к точному коммиту, чтобы исключить выдачу старой версии из кэша ветки `main`. Это обход ограничений российских провайдеров, которые обрывают крупные ответы Cloudflare примерно после первых 16 КиБ. Относительные ссылки внутри CSS автоматически загружают шрифты и заставку через тот же маршрут. Все страницы подключают локальный `main.min.js?v=54`, его сжатый размер меньше порога. Исходники `styles.css` и `main.js` напрямую в HTML не используются.

Описание ограничения со стороны Cloudflare: https://blog.cloudflare.com/russian-internet-users-are-unable-to-access-the-open-internet/

После изменения исходников заново собрать production-файлы и поднять номера версий во всех HTML-файлах. Если менялся CSS, сначала опубликовать коммит со свежими `home.min.css` и `styles.min.css`, затем указать его короткий SHA в jsDelivr URL и опубликовать второй коммит с HTML. Главный CSS очищается по фактически используемой разметке `index.html` и классам из `main.js`.

```bash
mkdir -p /tmp/mentorios-build-home
npx --yes purgecss@7.0.2 --css styles.css --content index.html main.js --output /tmp/mentorios-build-home
npx --yes clean-css-cli@5.6.3 -O2 -o home.min.css /tmp/mentorios-build-home/styles.css
npx --yes clean-css-cli@5.6.3 -O2 -o styles.min.css styles.css
npx --yes terser@5.44.0 main.js --compress --mangle --output main.min.js
```

Проверка:

```bash
rg -n 'main\.min\.js\?v=|(?:home|styles)\.min\.css\?v=' *.html
```

HTML-страницы отдаются с `Cache-Control: no-cache, must-revalidate`, поэтому браузер перепроверяет актуальную разметку после каждого обновления; версионированные статические ресурсы продолжают кэшироваться.

## Аналитика

Яндекс Метрика `111247225` загружается динамически только после принятия cookie-баннера. До согласия запрос к `mc.yandex.ru` не выполняется. Факт принятия хранится в `localStorage` под ключом `mentori_cookie_consent_v1` и содержит уникальный ID, дату и способ принятия.

Согласием считаются кнопка «Хорошо», взаимодействие с элементом сайта или прокрутка после 5 секунд. Переход по ссылке политики внутри баннера согласие не создаёт.

UTM-параметры и `yclid` хранятся до конца визита в `sessionStorage` под ключом `mentori_visit_attribution_v1`. Формы заявки на сайте нет, поэтому эти параметры используются только в рамках текущего визита и аналитики переходов. Отдельного серверного журнала согласий нет.

`main.js` отправляет следующие JavaScript-события:

| Идентификатор цели | Событие |
|---|---|
| `click_telegram` | Переход в Telegram |
| `click_phone` | Нажатие на телефон |
| `click_email` | Нажатие на email |
| `cta_contact` | Нажатие кнопки «Консультация», другого CTA контакта или ссылки MAX |
| `blog_article_open` | Открытие статьи из блога |

В Яндекс Метрике цели из таблицы созданы с типом `JavaScript-событие` и указанными идентификаторами. Автоцели Метрики работают дополнительно и не заменяют эти события.

- Файл подтверждения Яндекс Вебмастера `yandex_dadaa969d58e5279.html` не перенаправляется.

После публикации новой статьи или важного изменения:

1. Обновить `lastmod` страницы в `sitemap.xml`.
2. Проверить, что страница открывается с кодом `200` по HTTPS.
3. Проверить canonical, title, description, H1 и внутренние ссылки.
4. Отправить URL на переобход в Яндекс Вебмастере.
5. Убедиться, что актуальный `sitemap.xml` принят Вебмастером.

## Публикация

GitHub `main` является источником истины. Рабочий сайт размещён на VPS `5.181.109.125` в `/var/www/mentorios-site`; Nginx-конфигурация хранится в репозитории как `nginx/mentorios-site2.conf` и на сервере как `/etc/nginx/sites-available/mentorios-site2`.

Сначала сохранить резервную копию текущей серверной версии. Затем опубликовать файлы без массового удаления содержимого каталога, проверить Nginx и только после этого обновить `main`:

```bash
ssh new-server 'tar -czf /root/backups/mentorios-site-before-YYYYMMDD-HHMMSS.tar.gz -C /var/www mentorios-site'
rsync -az --delay-updates assets/ new-server:/var/www/mentorios-site/assets/
rsync -az --delay-updates styles.min.css home.min.css main.min.js site-refresh.css new-server:/var/www/mentorios-site/
rsync -az --delay-updates *.html robots.txt sitemap.xml llms.txt new-server:/var/www/mentorios-site/
git add -A
git commit -m "Describe the site update"
git push origin HEAD:main
```

После публикации проверить `https://mentorios.tech/`, чистые адреса, перенаправления со старых `.html`-адресов и файл подтверждения Яндекса. Вложения с компьютера могут иметь права `600`: перед выгрузкой публичным изображениям нужны права `644`, иначе Nginx ответит `403`. Проверять по HTTPS не только HTML, но и новые изображения, CSS, JS; сравнивать контрольные суммы с проверенной сборкой.

Конфигурацию Nginx переносить и перезагружать только при реальном изменении маршрутов или серверных настроек. Для добавления `/portfolio` изменений Nginx не требуется. Не копировать весь рабочий каталог: в нём теперь есть зависимости и инструменты сборки, не предназначенные для публикации.
